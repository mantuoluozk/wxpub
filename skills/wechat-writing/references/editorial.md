# 成稿与编辑

## 起草

- 写前用一两句确定读者、读者要解决的问题，以及全文最值得说的判断。长篇需要梳理论证时，参考 `upstream/wewrite/wewrite-write/references/article-brief.md`；按题材选结构。
- 第一段直接交代判断、具体发现或操作结果。每一段增加证据、步骤、限制或判断。重复的段合并，能用一句讲清的直接写一句。
- 按证据决定篇幅。优先使用具体事实、必要的例子和可复制的命令；表格只用于能对齐口径的对比。FAQ、金句、总结、引导互动和固定节数按稿件需要选用。
- 有作者样文时，参考一两篇同类文章的开头、句长、断句和收尾。经历和第一手观察只用作者实际提供的材料。素材撑不起某个判断时，缩小范围或注明边界。
- 版本号、实测数据、引用、比较条件与原文核对。来源或条件明确写出来，区分事实、推断和作者判断。已有事实核查文件时按项目约定更新。

## 删改

读取 `upstream/humanizer-zh/SKILL.md`。先删复读段、背景套话、预告和空泛结尾，再修妨碍理解的句子。保留事实、数字、代码、链接、归因及不确定性。保留原有 Markdown 和 YAML；更改已经核对过的事实时重核对应来源。写完从头通读一遍，确认读者能在开头看懂这篇要说什么。

## 学习作者文风

当前稿直接从用户给的样文学习。需要下次继续复用时，才使用 WeWrite 本地范文库，安装命令为 `uv tool install wewrite`。用户明确标为本人文章时，用 `wewrite exemplar <成稿路径> --user-authored`，用 `wewrite exemplar --list` 查看。后续起草时运行 `wewrite home` 定位状态目录，从其中的 `exemplars/index.yaml` 找到与本次稿件同类的本人范文，最多读两篇；状态目录不存在或没有匹配样文时，直接用当前材料起草。学习现有 WeWrite 任务的人工改稿时，读 `upstream/wewrite/wewrite-learn/references/learn-edits.md`；没有任务时，可先对读用户提供的前后两稿，由作者确认哪些改法值得沿用。范文和作者稿放在本机，成稿只采用与当前体裁相关的偏好。
